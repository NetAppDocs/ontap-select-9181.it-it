[[phases-of-storage-configuration]]
== Fasi della configurazione dello storage

Le principali fasi di configurazione dello storage host ONTAP Select includono le seguenti:

* Prerequisiti per la fase di pre-implementazione
+
** Assicurarsi che ogni host hypervisor sia configurato e pronto per una distribuzione di ONTAP Select.
** La configurazione comprende le unità fisiche, i controller RAID e i gruppi RAID, le LUN, nonché la relativa preparazione della rete.
** Questa configurazione viene eseguita al di fuori di ONTAP Select.


* Configurazione tramite l'utilità di amministrazione dell'hypervisor
+
** È possibile configurare determinati aspetti dello storage utilizzando l'utilità di amministrazione dell'hypervisor (ad esempio, vSphere in un ambiente VMware).
** Questa configurazione viene eseguita al di fuori di ONTAP Select.


* Configurazione tramite l'utility di amministrazione ONTAP Select Deploy
+
** È possibile utilizzare l'utilità di amministrazione Deploy per configurare le strutture di storage logico principali.
** Questa operazione viene eseguita esplicitamente tramite comandi CLI oppure automaticamente dall'utility durante la distribuzione.


* Configurazione post-implementazione
+
** Dopo che l'implementazione di ONTAP Select è stata completata, è possibile configurare il cluster utilizzando la ONTAP CLI o System Manager.
** Questa configurazione viene eseguita al di fuori di ONTAP Select Deploy.






[[managed-versus-unmanaged-storage]]
== Archiviazione gestita rispetto a quella non gestita

Lo storage a cui si accede e che viene controllato direttamente da ONTAP Select è storage gestito. Qualsiasi altro storage sullo stesso host hypervisor è storage non gestito.



[[homogeneous-physical-storage]]
=== storage fisico omogeneo

Tutte le unità fisiche che compongono lo storage gestito ONTAP Select devono essere omogenee. Ovvero, tutto l'hardware deve essere identico per quanto riguarda le seguenti caratteristiche:

* Tipo (SAS, NL-SAS, SATA, SSD)
* Velocità (RPM)

[[characteristics-of-the-local-storage-components]]
=== Caratteristiche dei componenti dello storage locale

Esistono diversi concetti che si applicano ai componenti di storage locale utilizzati in un ambiente ONTAP Select. È importante familiarizzare con questi concetti prima di prepararsi per una distribuzione di ONTAP Select. Tali concetti sono suddivisi per categoria: gruppi RAID e LUN, pool di storage e dischi virtuali.



==== Raggruppamento di unità fisiche in gruppi RAID e LUN

È possibile collegare localmente uno o più dischi fisici al server host e renderli disponibili a ONTAP Select. I dischi fisici vengono assegnati a gruppi RAID, che vengono poi presentati al sistema operativo host dell'hypervisor come una o più LUN. Ciascuna LUN viene presentata al sistema operativo host dell'hypervisor come un disco rigido fisico.

Quando si configura un host ONTAP Select, è necessario tenere presente quanto segue:

* Tutto lo storage gestito deve essere accessibile tramite un singolo controller RAID
* A seconda del produttore, ogni controller RAID supporta un numero massimo di unità per gruppo RAID




==== Uno o più gruppi RAID

Ogni host ONTAP Select deve avere un singolo controller RAID. È necessario creare un singolo gruppo RAID per ONTAP Select. Tuttavia, in determinate situazioni potrebbe essere opportuno creare più di un gruppo RAID. Fare riferimento a link:reference_plan_best_practices.html["Sintesi delle migliori pratiche"].



[[storage-pool-considerations]]
=== Considerazioni relative ai pool di storage

Esistono diverse problematiche relative ai pool di storage di cui è opportuno essere a conoscenza durante la preparazione all'implementazione ONTAP Select.


NOTE: In un ambiente VMware, un pool di storage è sinonimo di datastore VMware.



==== Pool di storage e LUN

Ogni LUN viene vista come un disco locale sull'host hypervisor e può far parte di un pool di storage. Ogni pool di storage è formattato con un file system che il sistema operativo dell'host hypervisor può utilizzare.

È necessario assicurarsi che i pool di storage vengano creati correttamente come parte di una distribuzione ONTAP Select. È possibile creare un pool di storage utilizzando il tool di amministrazione dell'hypervisor. Ad esempio, con VMware è possibile utilizzare il client vSphere per creare un pool di storage. Il pool di storage viene quindi passato all'utilità di amministrazione ONTAP Select Deploy.



[[manage-the-virtual-disks-on-esxi]]
=== Gestire i dischi virtuali su ESXi

Esistono diverse problematiche relative ai dischi virtuali di cui è necessario essere a conoscenza durante la preparazione all'implementazione di ONTAP Select.



==== Dischi virtuali e file system

Alla macchina virtuale ONTAP Select vengono allocate più unità disco virtuali. Ogni disco virtuale è in realtà un file contenuto in un pool di storage e gestito dall'hypervisor. Esistono diversi tipi di dischi utilizzati da ONTAP Select, principalmente dischi di sistema e dischi dati.

È inoltre opportuno tenere presente quanto segue in merito ai dischi virtuali:

* Il pool di storage deve essere disponibile prima che sia possibile creare i dischi virtuali.
* Non è possibile creare i dischi virtuali prima della creazione della macchina virtuale.
* È necessario utilizzare l'utility di amministrazione ONTAP Select Deploy per creare tutti i dischi virtuali (ovvero, un amministratore non deve mai creare un disco virtuale al di fuori dell'utility Deploy).




==== Configurazione dei dischi virtuali

I dischi virtuali sono gestiti da ONTAP Select. Vengono creati automaticamente quando si crea un cluster utilizzando l'utilità di amministrazione Deploy.



[[illustration-of-the-external-storage-environment-on-esxi]]
== Illustrazione dell'ambiente di archiviazione esterna su ESXi

La soluzione ONTAP Select vNAS consente a ONTAP Select di utilizzare datastore residenti su storage esterno all'host hypervisor. È possibile accedere ai datastore tramite la rete utilizzando VMware vSAN o direttamente su un array di storage esterno.

ONTAP Select può essere configurato per utilizzare i seguenti tipi di datastore di rete VMware ESXi esterni all'host hypervisor:

* vSAN (Virtual SAN)
* VMFS
* NFS




[[vsan-datastores]]
=== Datastore vSAN

Ogni host ESXi può avere uno o più datastore VMFS locali. Normalmente questi datastore sono accessibili solo all'host locale. Tuttavia, VMware vSAN consente a ciascuno degli host in un cluster ESXi di condividere tutti i datastore del cluster come se fossero locali.
