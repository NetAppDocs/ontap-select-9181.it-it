[[general]]
== Generale

Ci sono diverse domande e risposte di carattere generale.

.Qual è la differenza tra ONTAP Select Deploy e ONTAP Select?
ONTAP Select Deploy è l'utility utilizzata per creare cluster ONTAP Select. Attualmente ONTAP Select Deploy è l'unico metodo disponibile per la creazione di un cluster di produzione. ONTAP Select Deploy può anche essere utilizzato per creare un cluster Select di valutazione, consentendo ai clienti di testare e documentare le effettive fasi di una distribuzione in produzione. ONTAP Select Deploy può anche convertire un cluster di valutazione in un cluster di produzione utilizzando una licenza Capacity Tier appropriata con capacità sufficiente a coprire lo spazio consumato durante la valutazione.

ONTAP Select Deploy è una macchina virtuale che contiene un'immagine di ONTAP Select. Durante l'installazione del cluster, ONTAP Select Deploy esegue diversi controlli per garantire che i requisiti minimi di ONTAP Select siano rispettati. La VM ONTAP Select Deploy e i cluster Select possono essere aggiornati separatamente.

.Come posso risolvere un problema di prestazioni con ONTAP Select?
Come per ONTAP su FAS, i dati sulle prestazioni devono essere raccolti utilizzando l'utility perfstat. Ecco un esempio di comando:

[listing]
----
perfstat8 –i N,m -t <sample time in minutes> --verbose --nodes=<filer IP> --diag-passwd=abcxyz --mode="cluster-mode" > <name of output file>
----
.Come posso accedere alla pagina dell'API Swagger per ONTAP Select Deploy?
[listing]
----
http://<Deploy-IP-Address/api/ui
----

NOTE: La versione v3 dell'API non è compatibile con le versioni precedenti dell'API. Una nuova procedura API è disponibile su  https://library.netapp.com/ecm/ecm_download_file/ECMLP2845694["Field Portal"^].

.È possibile eseguire il backup della macchina virtuale ONTAP Select utilizzando snapshot di VMware o di terze parti?
No. La ONTAP Select VM utilizza unità persistenti indipendenti, che sono escluse dagli snapshot basati su VMware. L'unico metodo supportato per il backup di ONTAP Select è SnapMirror o SnapVault.

.Dove posso trovare chiarimenti su domande non trattate in queste FAQ?
Contatta link:mailto:ng-ses-ontap-select@netapp.com["ng-ses-ontap-select@netapp.com"].



[[licenses-installation-upgrades-and-reverts]]
== Licenze, installazione, aggiornamenti e ripristini

Sono presenti diverse domande e risposte relative a licenze, installazione, aggiornamenti e ripristini.

.È possibile aggiornare ONTAP Select e ONTAP Select Deploy separatamente?
Sì. L'utilità ONTAP Select Deploy può essere aggiornata separatamente dal cluster ONTAP Select. Analogamente, il cluster ONTAP Select può essere aggiornato separatamente dall'utilità ONTAP Select Deploy.

.ONTAP Select può essere aggiornato utilizzando la stessa procedura di un cluster FAS?
Sì, la procedura di aggiornamento per un cluster Select è identica all'aggiornamento di un cluster FAS, sebbene il file binario di aggiornamento di ONTAP Select sia un download separato rispetto al file binario di aggiornamento di ONTAP su FAS.

.È possibile ripristinare ONTAP Select utilizzando la stessa procedura di un cluster FAS?
Sì, la procedura di ripristino per un cluster ONTAP Select è quasi identica alla procedura di ripristino per un cluster FAS. Tuttavia, ci sono alcune differenze:

* Solo le istanze aggiornate di ONTAP Select possono essere ripristinate, e solo fino alla versione di installazione originale. Le nuove installazioni non possono essere ripristinate a una versione precedente del codice, anche se ONTAP Select in generale supporta tale versione precedente.
* Per ONTAP Select (KVM) e ONTAP Select (ESXi) che utilizzano il software RAID, non è possibile ripristinare una versione precedente che non supporta il software RAID. Inoltre, una nuova installazione di ONTAP Select 9.5 o successiva su ESXi utilizza i driver di rete VMXNET3 e, quando possibile, il driver vNVMe. Queste nuove installazioni non possono essere ripristinate a versioni precedenti di ONTAP Select.
* Se la VM ONTAP Select è stata anche aggiornata a un'istanza Large (utilizzando la licenza Premium XL), il ripristino a una versione precedente alla 9.6 non è supportato, perché la funzionalità di istanza Large non è disponibile nelle versioni precedenti.


.ONTAP MetroCluster SDS richiede almeno una licenza Premium?
Sì.

.È possibile modificare la configurazione di rete del cluster ONTAP Select dopo l'installazione?
Le modifiche alle seguenti proprietà del cluster ONTAP Select vengono riconosciute da ONTAP Select Deploy tramite l'operazione di aggiornamento del cluster disponibile attraverso l'interfaccia utente, la CLI o l'API REST:

* Configurazione di rete (indirizzi IP, DNS, NTP, netmask e gateway)
* ONTAP Select cluster, nome del nodo e versione


Vengono inoltre riconosciute le seguenti modifiche alla macchina virtuale ONTAP Select:

* Nome della VM ONTAP Select e modifiche di stato (ad esempio, online o offline)
* Modifiche al nome della rete host e al nome del pool di storage


L'aggiornamento a ONTAP Select Deploy 2.6 abilita il supporto per queste modifiche per qualsiasi cluster ONTAP Select già distribuito ma non modificato rispetto alla configurazione originale. In altre parole, se le proprietà del cluster ONTAP Select menzionate sopra sono state modificate tramite System Manager o vCenter, l'aggiornamento a ONTAP Select Deploy 2.6 non risolverà queste incongruenze. Le modifiche alle proprietà di ONTAP Select devono essere prima annullate affinché ONTAP Select Deploy possa aggiungere i suoi metadati univoci a ciascuna VM ONTAP Select.

.È possibile modificare la configurazione di rete di ONTAP Select Deploy dopo l'installazione?
La modifica dei dettagli di rete dell'istanza Deploy dopo l'esecuzione in un ambiente non è supportata. Per ulteriori informazioni, consultare l'articolo della Knowledge Base link:https://kb.netapp.com/onprem/ontap/ONTAP_Select/Modifying_DNS_configuration_of_ONTAP_Deploy_instance["Modifica della configurazione DNS dell'istanza ONTAP Deploy"^].

.Come fa Deploy a rilevare che le licenze ONTAP Select sono state rinnovate?
La procedura è la stessa per tutte le licenze, sebbene i dettagli specifici varino a seconda che si tratti di una licenza Capacity Tier o Capacity Pool.

* ONTAP Select Deploy rileva se le licenze e i contratti di supporto vengono rinnovati con l'acquisto di un file di licenza aggiornato da NetApp. Il file di licenza (.NLF) include capacità, date di inizio e fine; viene generato su link:https://mysupport.netapp.com/site/["Sito di supporto NetApp"^], e quindi aggiornato sul server Deploy.
+

NOTE: È possibile caricare il file NLF nel server Deploy utilizzando le funzioni *Aggiungi* e *Aggiorna*. *Aggiungi* aggiunge nuove licenze al server, e *Aggiorna* aggiorna i file esistenti con informazioni quali capacità, licenza per nodo (standard, premium, premium XL), date di inizio e fine del supporto (licenza Capacity Tier) o date di inizio e fine dell'abbonamento (licenza Capacity Pool).

+

CAUTION: Non tentare di modificare il file di licenza. In tal caso, la chiave di sicurezza verrà invalidata e la licenza diventerà non valida.

* Una licenza *Capacity Tier* è una licenza permanente per nodo, associata al numero di serie del nodo ONTAP Select. Viene venduta con un contratto di supporto separato. Sebbene la licenza sia permanente, il contratto di supporto deve essere rinnovato per accedere agli aggiornamenti di ONTAP Select e per ricevere assistenza dal supporto tecnico NetApp. Un contratto di supporto attivo è inoltre necessario per modificare i parametri della licenza, come la capacità o la dimensione del nodo.
+
Per acquistare un aggiornamento della licenza Capacity Tier, modificare i parametri o rinnovare un contratto di supporto, è necessario fornire il numero di serie del nodo al momento dell'ordine. I numeri di serie dei nodi Capacity Tier sono composti da nove cifre e iniziano con il numero '32'.

+
Una volta completato l'acquisto e generato il file di licenza, questo viene caricato sul server Deploy utilizzando la funzione *Update*.

* Una *licenza per pool di capacità* è un abbonamento che dà diritto a utilizzare uno specifico pool di capacità e una determinata dimensione dei nodi (standard, premium, premium XL) per implementare uno o più cluster. L'abbonamento include il diritto di utilizzare una licenza e il supporto per un periodo di tempo specificato. Il diritto di utilizzare la licenza e il contratto di supporto hanno date di inizio e fine prestabilite.


.Come fa Deploy a rilevare se i nodi hanno licenze o contratti di supporto rinnovati?
L'acquisto, la generazione e il caricamento di un file di licenza aggiornato sono le fasi con cui Deploy rileva le licenze e i contratti di supporto rinnovati.

Se la data di scadenza di un contratto di supporto Capacity Tier è trascorsa, il nodo può continuare a funzionare, ma non sarà possibile scaricare e installare aggiornamenti ONTAP o chiamare il supporto tecnico NetApp per assistenza senza prima aggiornare il contratto di supporto.

Se un abbonamento a un Capacity Pool scade, il sistema invia prima un avviso, ma dopo 30 giorni, se il sistema si arresta, non si riavvierà finché non verrà installato un abbonamento aggiornato sul server Deploy.



[[storage]]
== Storage

Esistono diverse domande e risposte relative allo storage.

.Una singola istanza di ONTAP Select Deploy può creare cluster sia su ESXi che su KVM?
Sì. ONTAP Select Deploy può essere installato sia su KVM che su ESXi ed entrambe le installazioni possono creare cluster ONTAP Select su entrambi gli hypervisor.

.È vCenter richiesto per ONTAP Select su ESXi?
Se gli host ESXi dispongono di una licenza adeguata, non è necessario che siano gestiti da un vCenter Server. Tuttavia, se gli host sono gestiti da un vCenter Server, è necessario configurare ONTAP Select Deploy per utilizzare tale vCenter Server. In altre parole, non è possibile configurare gli host ESXi come autonomi in ONTAP Select Deploy se sono gestiti attivamente da un vCenter Server. Si noti che la VM ONTAP Select Deploy si basa su vCenter per tracciare tutte le migrazioni di VM ONTAP Select tra host ESXi dovute a un evento vMotion o VMware HA.

.Che cos'è RAID software?
ONTAP Select può utilizzare server senza controller RAID hardware. In questo caso, la funzionalità RAID viene implementata via software. Quando si utilizza il RAID software, sono supportate sia le unità SSD che NVMe. I dischi di avvio e core di ONTAP Select devono comunque risiedere all'interno di una partizione virtualizzata (pool di storage o datastore). ONTAP Select utilizza RD2 (partizionamento root-data-data) per partizionare le unità SSD. Pertanto, la partizione root di ONTAP Select risiede sugli stessi dischi fisici utilizzati per gli aggregati di dati. Tuttavia, l'aggregato root e i dischi virtualizzati di avvio e core non vengono conteggiati ai fini della licenza di capacità.

Tutti i metodi RAID disponibili su AFF/FAS sono disponibili anche per ONTAP Select. Ciò include RAID 4, RAID DP e RAID-TEC. Il numero minimo di SSD varia a seconda del tipo di configurazione RAID scelta. Le best practice richiedono la presenza di almeno uno spare. Gli spare e i dischi di parità non vengono conteggiati ai fini della licenza di capacità.

.In che modo il RAID software è diverso da una configurazione RAID hardware?
Software RAID è un livello dello stack software di ONTAP. Software RAID offre un maggiore controllo amministrativo perché le unità fisiche vengono partizionate e sono disponibili come dischi raw all'interno della ONTAP Select VM. Al contrario, con hardware RAID, è solitamente disponibile un'unica LUN di grandi dimensioni che può essere suddivisa per creare i VMDISK visualizzati all'interno di ONTAP Select. Software RAID è disponibile come opzione e può essere utilizzato al posto di hardware RAID.

Alcuni dei requisiti per il software RAID sono i seguenti:

* Supportato per ESXi e KVM
+
** A partire da ONTAP Select 9.14.1, è stato ripristinato il supporto per l'hypervisor KVM. In precedenza, il supporto per l'hypervisor KVM era stato rimosso in ONTAP Select 9.10.1.


* Dimensioni dei dischi fisici supportati: 200GB – 32TB
* Supportato solo nelle configurazioni DAS
* Compatibile con SSD o NVMe
* Richiede una licenza ONTAP Select Premium o Premium XL
* Il controller RAID hardware deve essere assente o disabilitato oppure deve funzionare in modalità SAS HBA
* È necessario utilizzare un pool di storage LVM o un datastore basato su una LUN dedicata per i dischi di sistema: core dump, boot/NVRAM e Mediator.


.ONTAP Select per KVM supporta più aggregazioni di schede di rete?
Quando si installa su KVM, è necessario utilizzare un singolo bond e un singolo bridge. Un host con due o quattro porte fisiche deve avere tutte le porte nello stesso bond.

.In che modo ONTAP Select segnala o avvisa in caso di guasto di un disco fisico o di una NIC nell'host hypervisor? ONTAP Select recupera queste informazioni dall'hypervisor o il monitoraggio deve essere impostato a livello di hypervisor?
Quando si utilizza un controller RAID hardware, ONTAP Select è in gran parte inconsapevole dei problemi sottostanti del server. Se il server è configurato secondo le nostre best practice, dovrebbe esistere un certo grado di ridondanza. Consigliamo RAID 5/6 per sopravvivere ai guasti dei dischi. Per le configurazioni RAID software, ONTAP è responsabile dell'emissione di avvisi in caso di guasto del disco e, se è disponibile un'unità di riserva, dell'avvio della ricostruzione del disco.

È consigliabile utilizzare almeno due schede di rete fisiche per evitare un single point of failure a livello di rete. NetApp raccomanda che i gruppi di porte Data, Mgmt e Internal abbiano il teaming e il bonding delle NIC configurati con due o più uplink nel team o nel bond. Tale configurazione garantisce che, in caso di guasto di un uplink, lo switch virtuale sposti il traffico dall’uplink guasto a un uplink funzionante nel team di NIC. Per dettagli sulla configurazione di rete consigliata, vedere link:reference_plan_best_practices.html#networking["Sintesi delle migliori pratiche: Networking"].

Tutti gli altri errori vengono gestiti da ONTAP HA nel caso di un cluster a due o quattro nodi. Se è necessario sostituire il server hypervisor e il cluster ONTAP Select deve essere ricostituito con un nuovo server, consultare _Posso ripristinare un nodo ONTAP Select?_.

.È possibile ripristinare un nodo ONTAP Select?
Contattare il Supporto Tecnico NetApp se è necessario ripristinare un nodo ONTAP Select, ad esempio se una VM ONTAP Select o un host viene completamente perso o un cluster a nodo singolo viene eliminato accidentalmente. Per ulteriori informazioni, consultare l'articolo della Knowledge Base link:https://kb.netapp.com/on-prem/ontap/ontap-select/Select-KBs/ONTAP_Select_node_VM_recovery_in_case_of_disaster["Ripristino della VM del nodo ONTAP Select in caso di disastro"^].

.Qual è la dimensione massima del datastore supportata da ONTAP Select?
Tutte le configurazioni, inclusa vSAN, supportano 400TB di storage per nodo ONTAP Select.

Quando si installa su datastore di dimensioni superiori alla dimensione massima supportata, è necessario utilizzare Capacity Cap durante la configurazione del prodotto.

.Come posso aumentare la capacità di un nodo ONTAP Select?
ONTAP Select Deploy include un flusso di lavoro per l'aggiunta di storage che supporta l'operazione di espansione della capacità su un nodo ONTAP Select. È possibile espandere lo storage gestito utilizzando lo spazio dello stesso datastore (se è ancora disponibile) oppure aggiungendo spazio da un datastore separato. La combinazione di datastore locali e remoti nello stesso aggregato non è supportata.

L'aggiunta di storage supporta anche il RAID software. Tuttavia, nel caso del RAID software, è necessario aggiungere unità fisiche aggiuntive alla VM ONTAP Select. In questo caso, l'aggiunta di storage è simile alla gestione di un array FAS o AFF. Quando si aggiunge storage a un nodo ONTAP Select utilizzando il RAID software, è necessario tenere conto delle dimensioni dei gruppi RAID e delle dimensioni delle unità.

.ONTAP Select supporta i datastore di tipo vSAN o array esterni?
ONTAP Select Deploy e ONTAP Select per ESXi supportano la configurazione di un cluster a nodo singolo ONTAP Select utilizzando un vSAN o un tipo di datastore di array esterno per il suo pool di storage.

ONTAP Select Deploy e ONTAP Select for KVM supportano la configurazione di un cluster a nodo singolo ONTAP Select utilizzando un tipo di pool di storage logico condiviso su array esterni. I pool di storage possono essere basati su iSCSI o FC/FCoE. Altri tipi di pool di storage non sono supportati.

Sono supportati i cluster HA multi-nodo su storage condiviso.

.ONTAP Select supporta cluster multi-nodo su vSAN o altri storage esterni condivisi, inclusi alcuni stack HCI?
I cluster multi-nodo che utilizzano storage esterno (multi-node vNAS) sono supportati sia per ESXi che per KVM. La combinazione di hypervisor nello stesso cluster non è supportata. Un'architettura HA su storage condiviso implica comunque che ogni nodo in una coppia HA disponga di una copia speculare dei dati del partner. Tuttavia, un cluster multi-nodo offre i vantaggi delle operazioni non disruptive di ONTAP, a differenza di un cluster a nodo singolo che si basa su VMware HA o KVM Live Motion.

Sebbene ONTAP Select Deploy aggiunga il supporto per più ONTAP Select VM sullo stesso host, non consente a tali istanze di far parte dello stesso cluster ONTAP Select durante la creazione del cluster. Per gli ambienti ESXi, NetApp consiglia di creare regole di anti-affinità per le VM in modo che VMware HA non tenti di migrare più ONTAP Select VM dallo stesso cluster ONTAP Select su un singolo host ESXi. Inoltre, se ONTAP Select Deploy rileva che una vMotion amministrativa (avviata dall'utente) o una live migration di una ONTAP Select VM ha comportato una violazione delle nostre best practice, come ad esempio due nodi ONTAP Select che finiscono sullo stesso host fisico, ONTAP Select Deploy pubblica un avviso nell'interfaccia utente e nel registro di Deploy. L'unico modo in cui ONTAP Select Deploy viene a conoscenza della posizione della VM ONTAP Select è a seguito di un'operazione di Cluster Refresh, che è un'operazione manuale che l'amministratore di ONTAP Select Deploy deve avviare. Non esiste alcuna funzionalità in ONTAP Select Deploy che consenta il monitoraggio proattivo e l'avviso è visibile solo tramite l'interfaccia utente di Deploy o il registro. In altre parole, questo avviso non può essere inoltrato a un'infrastruttura di monitoraggio centralizzata.

.ONTAP Select supporta NSX VXLAN di VMware?
Sono supportati i gruppi di porte VXLAN NSX-V. Per HA multi-nodo, incluso ONTAP MetroCluster SDS, assicurati di configurare l'MTU della rete interna tra 7500 e 8900 (anziché 9000) per gestire l'overhead VXLAN. L'MTU della rete interna può essere configurato con ONTAP Select Deploy durante la distribuzione del cluster.

.ONTAP Select supporta la migrazione live di KVM?
Le VM ONTAP Select che vengono eseguite su pool di storage di array esterni supportano le migrazioni live di virsh.

.Ho bisogno di ONTAP Select Premium per vSAN AF?
No, tutte le versioni sono supportate, indipendentemente dal fatto che l'array esterno o le configurazioni vSAN siano all flash.

.Quali impostazioni vSAN FTT/FTM sono supportate?
La VM Select eredita i criteri di archiviazione del datastore vSAN e non presenta restrizioni sulle impostazioni FTT/FTM. Tuttavia, si noti che, a seconda delle impostazioni FTT/FTM, le dimensioni della VM ONTAP Select possono essere significativamente maggiori della capacità configurata durante la configurazione. ONTAP Select utilizza VMDK thick-eager azzerati che vengono creati durante la configurazione. Per evitare di influire su altre VM che utilizzano lo stesso datastore condiviso, è importante fornire una capacità libera sufficiente nel datastore per ospitare le dimensioni effettive della VM Select, calcolate in base alla capacità Select e alle impostazioni FTT/FTM.

.È possibile eseguire più nodi ONTAP Select sullo stesso host se appartengono a cluster Select diversi?
È possibile configurare più nodi ONTAP Select sullo stesso host solo per le configurazioni vNAS, a condizione che questi nodi non facciano parte dello stesso cluster ONTAP Select. Questa configurazione non è supportata per le configurazioni DAS, poiché più nodi ONTAP Select sullo stesso host fisico entrerebbero in competizione per l'accesso al controller RAID.

.È possibile far sì che un host con una singola porta 10GE esegua ONTAP Select e se è disponibile sia per ESXi che per KVM?
È possibile utilizzare una singola porta 10GE per connettersi alla rete esterna. Tuttavia, NetApp consiglia di utilizzarla solo in ambienti con fattore di forma ridotto. Questo è supportato sia con ESXi che con KVM.

.Quali processi aggiuntivi è necessario eseguire per effettuare una migrazione live su KVM?
È necessario installare ed eseguire i componenti open-source CLVM e pacemaker (pcs) su ciascun host che partecipa alla migrazione live. Ciò è necessario per accedere agli stessi gruppi di volumi su ciascun host.



[[vcenter]]
== vCenter

Esistono diverse domande e risposte relative a VMware vCenter.

.Come comunica ONTAP Select Deploy con vCenter e quali porte del firewall devono essere aperte?
ONTAP Select Deploy utilizza l'API VMware VIX per comunicare con il vCenter, l'host ESXi o entrambi. La documentazione VMware afferma che la connessione iniziale a un vCenter Server o a un host ESXi viene effettuata tramite HTTPS/SOAP sulla porta TCP 443. Questa è la porta per HTTP sicuro su TLS/SSL. In secondo luogo, viene aperta una connessione all'host ESXi su un socket sulla porta TCP 902. I dati che transitano su questa connessione vengono crittografati con SSL. Inoltre, ONTAP Select Deploy emette un `PING` comando per verificare che vi sia un host ESXi che risponde all'indirizzo IP specificato.

ONTAP Select Deploy deve inoltre essere in grado di comunicare con gli indirizzi IP di gestione del nodo e del cluster ONTAP Select come segue:

* Ping
* SSH (porta 22)
* SSL (porta 443)


Per i cluster a due nodi, ONTAP Select Deploy ospita le mailbox del cluster. Ciascun nodo ONTAP Select deve essere in grado di raggiungere ONTAP Select Deploy tramite iSCSI (porta 3260).

Per i cluster multi-nodo, la rete interna deve essere completamente aperta (senza NAT o firewalls).

.Di quali diritti vCenter ha bisogno ONTAP Select Deploy per creare cluster ONTAP Select?
L'elenco dei vCenter diritti richiesti è disponibile qui: link:reference_plan_ots_vcenter.html["Server VMware vCenter"].



[[ha-and-clusters]]
== HA e cluster

Sono presenti diverse domande e risposte relative alle coppie HA e ai cluster.

.Qual è la differenza tra un cluster a quattro, sei o otto nodi e un cluster ONTAP Select a due nodi?
A differenza dei cluster a quattro, sei e otto nodi, in cui la VM ONTAP Select Deploy viene utilizzata principalmente per creare il cluster, un cluster a due nodi si affida continuamente alla VM ONTAP Select Deploy per il quorum HA. Se la VM ONTAP Select Deploy non è disponibile, i servizi di failover vengono disabilitati.

.Che cos'è MetroCluster SDS?
MetroCluster SDS è un'opzione di replica sincrona a basso costo che rientra nella categoria delle soluzioni di Business Continuity MetroCluster di NetApp. È disponibile solo con ONTAP Select, a differenza di NetApp MetroCluster che è disponibile su FAS Hybrid Flash, AFF e NetApp Private Storage for Cloud.

.In che cosa la MetroCluster SDS è diversa da NetApp MetroCluster?
MetroCluster SDS offre una soluzione di replica sincrona e rientra tra le soluzioni NetApp MetroCluster. Tuttavia, una differenza fondamentale risiede nel tipo di connettività (sono supportate solo reti IP, non FC e IP).

.Qual è la differenza tra un cluster ONTAP Select a due nodi e un ONTAP MetroCluster SDS a due nodi?
Un cluster a due nodi è definito come un cluster in cui entrambi i nodi si trovano nello stesso data center entro 300 m l'uno dall'altro. In genere, entrambi i nodi dispongono di uplink allo stesso switch di rete o a un insieme di switch di rete collegati tramite un Inter-Switch Link.

Il MetroCluster SDS a due nodi è definito come un cluster con nodi fisicamente separati (stanze diverse, edifici diversi o data center diversi) e le connessioni uplink di ciascun nodo sono collegate a switch di rete separati. Sebbene MetroCluster SDS non richieda hardware dedicato, l'ambiente deve supportare i requisiti minimi di latenza (5 ms RTT e 5 ms di jitter per un totale massimo di 10 ms).

MetroCluster SDS è una funzionalità premium e richiede una licenza Premium o Premium XL. Una licenza Premium supporta la creazione di VM sia Small che Medium, nonché supporti HDD e SSD. Tutte queste configurazioni sono supportate.

.Il sistema ONTAP MetroCluster SDS richiede un'archiviazione locale (DAS)?
ONTAP MetroCluster SDS supporta tutti i tipi di configurazioni di storage (DAS e vNAS).

.ONTAP MetroCluster SDS supporta il controller RAID software?
Sì, il RAID software è supportato con supporti SSD sia su KVM che su ESXi.

.ONTAP MetroCluster SDS supporta sia gli SSD che i supporti di memorizzazione tradizionali?
Sì, sebbene sia necessaria una licenza Premium, questa licenza supporta sia macchine virtuali di piccole e medie dimensioni sia unità SSD e supporti di memorizzazione tradizionali.

.ONTAP MetroCluster SDS supporta cluster a quattro nodi e di dimensioni maggiori?
No, solo i cluster a due nodi con un Mediator possono essere configurati come MetroCluster SDS.

.Quali sono i requisiti per ONTAP MetroCluster SDS?
I requisiti sono i seguenti:

* Tre data center (uno per l'ONTAP Select Deploy Mediator e uno per ciascun nodo)
* 5ms RTT e 5ms jitter per un totale massimo di 10ms
* 125ms RTT e una larghezza di banda minima di 5Mbps tra ONTAP Select Deploy Mediator e ciascun nodo ONTAP Select
* Una licenza Premium o Premium XL


.ONTAP Select supporta vMotion o VMware HA?
Le VM ONTAP Select che vengono eseguite su datastore vSAN o datastore array esterni (in altre parole, implementazioni vNAS) supportano vMotion, DRS e la funzionalità VMware HA.

.ONTAP Select supporta Storage vMotion?
Lo storage vMotion è supportato per tutte le configurazioni, inclusi i cluster ONTAP Select a nodo singolo e multi-nodo e la VM ONTAP Select Deploy. Lo storage vMotion può essere utilizzato per migrare la VM ONTAP Select o la VM ONTAP Select Deploy tra diverse versioni di VMFS (ad esempio, da VMFS 5 a VMFS 6), ma non è limitato a questo caso d'uso. La best practice è arrestare la VM prima di avviare un'operazione di storage vMotion. ONTAP Select Deploy deve eseguire la seguente operazione dopo che l'operazione di storage vMotion è stata completata:

[listing]
----
cluster refresh
----

NOTE: Un'operazione di storage vMotion tra diversi tipi di datastore non è supportata. In altre parole, le operazioni di storage vMotion tra datastore di tipo NFS e datastore VMFS non sono supportate. In generale, le operazioni di storage vMotion tra datastore esterni e datastore DAS non sono supportate.

.Il traffico HA tra i nodi ONTAP Select può essere eseguito su un vSwitch diverso e/o porte fisiche separate e/o utilizzando cavi IP punto-punto tra host ESXi?
Queste configurazioni non sono supportate. ONTAP Select non ha visibilità sullo stato dei collegamenti di rete fisici che trasportano il traffico dei client. Pertanto, ONTAP Select si affida all'heartbeat HA per garantire che la VM sia accessibile contemporaneamente ai client e al suo peer. Quando si verifica una perdita di connettività fisica, la perdita dell'heartbeat HA comporta un failover automatico sull'altro nodo, che è il comportamento desiderato.

Separare il traffico HA su un'infrastruttura fisica separata può comportare che una VM Select sia in grado di comunicare con la sua controparte ma non con i suoi client. Ciò impedisce il processo HA automatico e causa l'indisponibilità dei dati fino a quando non viene attivato un failover manuale.



[[mediator-service]]
== Servizio di mediazione

Esistono diverse domande e risposte relative al servizio di mediazione.

.Che cos'è il servizio Mediator?
Un cluster a due nodi si affida continuamente alla VM ONTAP Select Deploy per il quorum HA. Una VM ONTAP Select Deploy che partecipa a una negoziazione del quorum HA a due nodi viene etichettata come VM Mediator.

.Il servizio Mediator può essere remoto?
Sì. ONTAP Select Deploy, in qualità di Mediatore per una coppia HA a due nodi, supporta una latenza WAN fino a 500 ms RTT e richiede una larghezza di banda minima di 5 Mbps.

.Quale protocollo utilizza il servizio Mediator?
Il traffico del Mediator è iSCSI, ha origine sugli indirizzi IP di gestione del nodo ONTAP Select e termina sull'indirizzo IP di Deploy di ONTAP Select. Si noti che non è possibile utilizzare IPv6 per l'indirizzo IP di gestione del nodo ONTAP Select quando si utilizza un cluster a due nodi.

.Posso utilizzare un singolo servizio Mediator per più cluster HA a due nodi?
Sì. Ogni VM ONTAP Select Deploy può fungere da servizio Mediator comune per un massimo di 100 cluster a due nodi ONTAP Select.

.È possibile modificare la posizione del servizio Mediator dopo l'implementazione?
Sì. È possibile utilizzare un'altra macchina virtuale ONTAP Select Deploy per ospitare il servizio Mediator.

.ONTAP Select supporta i cluster estesi con (o senza) il Mediator?
Solo un cluster a due nodi con un Mediatore è supportato in un modello di implementazione HA esteso.
